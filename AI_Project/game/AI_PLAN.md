## 2. Per-fighter data refactor

- The sim keeps `this.chars = [charP1, charP2]`, and every former read of `PHYS` / `HURT` / `MOVES` goes through
  `this.C(f)` (the fighter's character). Fighter objects stay **plain data** (no character pointer), so they can be
  cloned by hand, hashed, and posted to a Web Worker.
- `phys` per character = `WORLD` (shared constants) + the character's own numbers. The stage width, margin, gravity,
  buffers and HP are world constants; walk / dash / back-dash speeds and `pushHalf` are per character. The pushbox
  separation becomes `pushHalf(a) + pushHalf(b)` (= 180 for Shinobi vs Shinobi, unchanged).
- Each character supplies `pickMove(btn, {air, down})` and `inputMask`. The Shinobi's mapping is the old `pickMove`
  verbatim; the Samurai maps `P -> light`, `S -> heavy`, and the ultimate is always `moves.ult`.
- **Input masking** (in the sim, not only in agents): bits outside `inputMask` are dropped *before* edge detection;
  `can.run === false` disables the double-tap-forward run event; `can.jump / can.crouch === false` mask `U` / `D`.
  Double-tap back (and `DASH`+back) is the back-dash for both characters.
- **Grounded back-dash**: characters without `phys.backhopV` get state `backdash` (no `vy`, slides at `backdashV` for
  `backdashFrames`, ends at `backdashTotal`). Forward dash length becomes `phys.dashTotal ?? 25` (Shinobi 25 unchanged).
- **Chip**: `chip <= 1` is a fraction of `dmg` (Samurai heavy 0.25 -> 53), larger values are absolute (Shinobi fan 25,
  crescent 175). Chip still cannot KO (unchanged Shinobi rule).
- **Crescent**: `projectile.kind = 'crescent'` spawns through the existing projectile path; it is not ducked by
  crouching (only the thrown kunai is), it knocks down via `spec.knockdown` / `spec.launch`, it is mid (both blocks work),
  `noScale`, and it is jumpable because its box is y 0..420.
- **Rounds**: `new Sim({ chars, autoReset })`. The training game keeps the old KO auto-reset; the arena disables it and
  runs rounds itself (`sim.newRound()` keeps meter, restores HP and positions).
- **Regression proof**: `replay_hash.mjs` recorded 3,600 frames of Shinobi vs Shinobi (all 9 moves incl. 5 ultimates,
  jumps, air attacks, crouch, run, hop, dash, blocks, KO reset) on the original code; final hash `39e93813`. After the
  refactor every frame's hash must match.

## 3. Clone strategy

`sim.clone()` is hand-written: two fighters (flat objects + the `buf` object copied field by field), projectiles
(shallow copy each, sharing the immutable `spec`), `comboShow`, `lastHit`, scalars; `events` start empty; `chars` is
shared (immutable). Tested by stepping a clone and the original with the same random inputs for 600 frames and
comparing `hash()` each frame; benchmarked against `structuredClone`.

`sim.hash()`: FNV-1a over float64 bits of every mutable field (fighters, buffers, projectiles, timers). Used for
determinism tests and as the Minimax transposition-table key.

## 4. Macro-actions (Samurai: 9)

`wait`, `walk_fwd`, `walk_back` (8 frames each), `dash_fwd`, `dash_back` (one press, then neutral until the dash ends),
`guard` (hold `B` 8 frames, keeps holding while in blockstun), `light`, `heavy` (one press, then neutral until the
move ends), `ult` (needs meter 100).

- Decision point: the fighter is free (`idle` / `walk` / `guard`) and its previous macro has finished. While committed
  there is exactly one action and no search runs.
- Legality filter: no `light` / `heavy` when the opponent's hurtbox is further than the move's measured box reach
  plus one dash; no `ult` without meter; no `dash_back` / `walk_back` when cornered within 40 units.
- Inside search the same macros are played forward with `clone()` + `step()` until the next decision point of either
  side (cap 40 frames). A side whose macro is still running has the single action "continue".

## 5. Evaluation (`eval.js`, weights in one exported object)

From the searching side's point of view, in HP units:
`hp` difference; `meter` difference (+ bonus when full); `range` error versus the light's measured reach; `commit`
(being in recovery / whiffing, a whiffed heavy weighs most); `corner` pressure; `knockdown` advantage; `threat` of a
pending projectile; plus a large terminal value for KO. Every term is documented in the file.

## 6. Agents

- **MinimaxAgent**: depth-limited simultaneous-move search, value `max_mine min_theirs`. This is pessimistic (it assumes
  the opponent sees our commitment and best-responds), which suits a disciplined duelist who never gambles.
  Alpha-beta on the inner min and across siblings, move ordering (previous best, attacks in range, guard, movement),
  iterative deepening under a node or time budget, transposition table keyed by `sim.hash()` + depth + pending
  programs. Leaves are "settled" (running macros finished) before evaluation so a committed attack is valued by its
  outcome, not mid-swing.
- **MctsAgent**: decoupled UCT. Each node holds separate UCB1 statistics per player; both choose independently; the
  joint child is keyed by the pair. Rollouts of 60-120 frames with a light random-but-legal macro policy (guard-biased
  when the opponent is in an attack's startup), `eval.js` squashed to [0,1] at the horizon. Final choice by visit
  count. Budget 16 ms or a fixed rollout count.
- **FuzzyAgent**: Mamdani inference. Inputs: distance (close / mid / far), own HP and opponent HP (low / mid / high),
  meter (empty / partial / full), opponent state (attacking / recovering / neutral, as membership degrees). Outputs:
  aggression and defence on [0,1], 16 rules, min implication, max aggregation, centroid defuzzification, then a small
  deterministic table + seeded RNG to pick the macro.
- **RandomAgent** (uniform legal macro) and **ScriptedAgent** (walk in, light in range, guard when the opponent swings,
  heavy on a whiff).
- **Difficulty** wrapper: Easy 2 ms / 22 f / 20 %, Normal 8 ms / 14 f / 8 %, Hard 16 ms / 9 f / 2 %, Master 50 ms in a
  Web Worker / 6 f / 0 %. A mistake replaces the chosen macro with a random legal one.

Agents get a **delayed, sanitised view**: the harness keeps a ring buffer of `sim.clone()`s, gives the agent the one
`reactionFrames` old, and zeroes the opponent's `buf`, `prev`, `tap*`, `ev*` and the derived held-button flags (asserted).
The agent extrapolates the view to "now" by stepping it with its own remembered inputs and a state-based guess for the
opponent (a walking opponent keeps walking, a guarding one keeps guarding), which is search on the snapshot, not
peeking. All randomness is seeded mulberry32; benchmark mode uses node / rollout budgets so runs replay bit-identically.

## 7. Benchmark plan

`arena.mjs`: best of 3, 99 s rounds (5,940 frames), HP-percentage decision at time-out, meter carried over, sides swapped
for half the matches, per-match seeds from `--seed`. Round-robin of Minimax, MCTS, Fuzzy, Random, Scripted and
GA-Minimax, Samurai vs Samurai, 200 matches per pairing. Win rate with 95 % Wilson intervals, draws, HP margin, damage,
hit/block ratio, ultimates, decision time (mean / p95), nodes or rollouts per decision. Sanity: every real agent > 90 %
vs Random; self-mirrors near 50 %; side-swap halves agree. Scaling curves: Minimax nodes and MCTS rollouts vs a fixed
opponent. Output in `docs/ai_benchmark.md` with PNG charts.

## 8. Risks

| Risk | Mitigation |
|---|---|
| The Samurai's light reaches 1036 units: from the default start (1,100 apart) a light already connects. Neutral may degenerate into "who presses first". | It is the measured art (README balance note). Measure first; if the mirror is degenerate, document it, and only then consider the pipeline fix (`BLADE` / elbow in `art/samurai`), never hand-edited boxes. |
| Compute: 2 CPU cores here; a 200-match round-robin with search on both sides is expensive. | Node / rollout budgets sized from measured cost (about 90 µs per Minimax node, 100-150 µs per MCTS rollout); two worker threads; report the budgets used. |
| Simultaneous-move maximin is very pessimistic and may turtle (guard forever). | Chip on the heavy and the timer penalise turtling; the eval rewards range control; reported as an observed behaviour if it happens. |
| Side bias (P1 is updated first in the sim loop). | Self-mirror and side-swap checks; if biased, investigate `update` / `resolvePush` order. |
| Reaction delay makes an agent misjudge its own state. | Extrapolate with its own remembered inputs (it knows what it pressed). |
| Browser frame rate with two searching agents on the main thread. | Budgets are per decision (about every 8 frames); Master runs in a Web Worker; the overlay only reads `thinking()`. |
